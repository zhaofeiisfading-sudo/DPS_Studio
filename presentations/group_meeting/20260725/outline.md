# DPS Studio 组会汇报最终大纲

完整逐页内容、素材映射和页面衔接见同目录的
[`presentation_outline.md`](presentation_outline.md)。

1. **DPS Studio：从原始 PDV 信号到可追溯的表观速度**  
   封面；界定当前项目是数值分析工作流，而非已发布 GUI。
2. **速度曲线连接实验信号与后续物理判断**  
   实验信号 → 拍频脊线 → 表观速度 → 物理分析。
3. **旧流程的核心风险不是界面陈旧，而是证据链不完整**  
   旧输出只是回归指纹；参数、谱证据和质量状态必须可追溯。
4. **Python 重建的价值是把算法、配置和验证放进同一工作流**  
   NumPy/SciPy、Matplotlib、PySide6/PyQtGraph、pytest/Ruff/mypy。
5. **新版处理链已打通表观速度闭环，物理修正仍被明确隔离**  
   已实现、正在完善、尚未实现三态处理链。
6. **可信输入从只读原始数据、SI 单位和显式列映射开始**  
   双通道独立 `SignalRecord`；不平滑、不插值、不重采样。
7. **STFT 将时变拍频转换为可追踪的时频脊线**  
   解释窗长、hop、NFFT 和真实 STFT/脊线图。
8. **脊线给出拍频轨迹，只有显式波长才能换算表观速度**  
   `v_app = λ₀ f_b / 2`；1550 nm 未确认；无 LiF 修正。
9. **双通道必须独立分析；质量量只提供诊断证据**  
   描述性谱对比度不是正式 SNR，不自动选通道。
10. **core/workflow 与 GUI 解耦，让数值链可以独立验证**  
    单向依赖、不可变对象、NaN/状态和 manifest。
11. **当前工作树已形成可运行闭环；质量门通过但尚未发布**  
    当前 `271 tests / 39 source files / 30 production files`。
12. **真实运行显示两通道结果同量级，但还不能自动判定“哪个更可信”**  
    Balanced 两通道真实速度图和安全解释。
13. **软件能运行不等于结果已达到科研使用标准**  
    弱信号、分支、质量阈值、波长、LiF、GUI 等缺口。
14. **下一阶段优先建立可信判据，再推进修正模型和 GUI**  
    非 AI 主线 → 通道决策 → 修正验证 → CLI/GUI → 部署。
15. **项目重点已从“跑通”转向“可信、可复现、可交付”**  
    收束当前成果、边界和近期重点。

视觉方向：只抽取 `Sigapore_presentation.pptx` 的深红/白色背景关系、
浅灰几何装饰和红色标题节奏；不复用模板正文、章节结构、页面布局、
参考文献、页码、动画或任何原始文本。最终图片后端固定为
`built-in image tool (image_gen)`，画面为 16:9。
