# DPS Studio 组会汇报：18 页结构

## 汇报定位

- 对象：课题组组会。
- 主线：原始双通道 PDV 电压 → STFT 时频表示 → 候选脊线 → 无符号表观速度 → 诊断与待验证边界。
- 目标：说明目前软件能复现什么、这些结果从哪里来、哪些物理解释尚不能成立。
- 视觉：16:9；暖白底、暗红、黑/深灰、浅灰；实验图保留原始配色；不使用装饰性彩色圆点、阴影或大面积圆角卡片。
- 编辑性：标题、正文、公式、表格、流程、时间线和标注全部使用 PowerPoint 原生对象；仅真实实验图以图片嵌入。

## 逐页安排

### 01 封面｜DPS Studio：从原始 PDV 信号到可追溯的表观速度

- 核心句：当前已建立可复现的数值处理路径，但物理校正与可信判据仍待实验验证。
- 内容：题目、组会汇报、日期；只保留一条暗红竖带与细线频率轨迹作为抽象装饰。
- 版式：左侧大标题，右下角三段原生文本“电压 / 时频 / 表观速度”。
- 科学边界：封面不出现“真实界面速度”“LiF 修正完成”等表述。

### 02 任务｜这次汇报要回答三个问题

- 核心句：解释输入、算法和结论边界，而不是只展示一条曲线。
- 三问：
  1. 原始电压如何变成随时间变化的拍频？
  2. 当前参数如何影响时间支持与频率稳定？
  3. 表观速度结果可以支持什么，仍不能支持什么？
- 术语首次定义：
  - PDV：Photon Doppler Velocimetry，光子多普勒测速。
  - 表观速度：由显式真空波长与拍频按当前模型换算的无符号速度量，尚未做 LiF、折射率或入射角修正。
- 版式：三个竖向编号块，底部一条“数据事实 / 数值处理 / 物理解释”边界线。

### 03 原始输入｜原始数据保留两路采集差异

- 核心句：两列电压分别读入，不平均、不融合、不平滑。
- 主图：`assets/real/raw_voltage_dual_channel.png`。
- 说明：时间列为第 0 列；`pdv_channel_1`/`pdv_channel_2` 分别为第 1/2 列；内部计算保持 SI 单位。
- 来源：`configs/demo_dual_profile.toml`、`scripts/run_demo_pipeline.py`、原始 CSV 的既有可视化。
- 版式：右侧 75% 主图，左侧三条原生文字说明。

### 04 原始波形的限制｜波形振荡并不直接给出频率何时改变

- 核心句：只看时域波形，无法稳定回答拍频在何时、以何种速度迁移。
- 内容：原生绘制的短时窗口示意；同一段信号在连续窗口内做 STFT；输出是时间—频率矩阵。
- 术语首次定义：
  - 拍频：参考光与运动表面反射光干涉形成的频率差。
  - STFT：Short-Time Fourier Transform，短时傅里叶变换。
- 版式：左“时域信号”，中“滑动 Hann 窗”，右“时间—频率图”，使用细灰线和暗红强调。
- 科学边界：示意图只解释算法，不冒充实验数据。

### 05 完整频谱｜完整单边频谱先交代能量分布

- 核心句：实际 Nyquist 约 20 GHz；数值脊线只在 0.05–2.0 GHz 搜索。
- 主图：`assets/real/full_stft_balanced_ch1.png`。
- 内容：图区分三个范围：完整单边频谱、0–2 GHz 分析显示、0.05–2.0 GHz 数值搜索。
- 版式：主图居中占 80%，上方一句结论，底部三段范围说明。
- 科学边界：完整频谱上限来自实际采样率，不硬编码或补造 20–40 GHz 数据。

### 06 候选脊线｜局部 STFT 中的亮带提供可追踪候选

- 核心句：每帧在固定搜索带内取离散峰，再用相邻三点对数幅值做亚频点精修。
- 图像：
  - `assets/real/local_stft_balanced_ch1.png`；
  - `assets/real/local_stft_ridge_balanced_ch1.png`。
- 内容：左图说明局部时频结构，右图说明离散峰、精修候选与相关频率诊断。
- 术语首次定义：
  - 脊线：每个 STFT 时间帧中被选中的候选频率轨迹。
  - 亚频点精修：用峰值频点及其左右相邻频点估计落在 FFT 网格之间的频率。
- 科学边界：当前不是动态规划，也没有物理分支识别或跳频阈值。

### 07 物理换算｜拍频不是速度；显式波长后才能换算

- 核心句：当前模型只给出无符号表观速度。
- 公式：`v_app(t) = λ₀ f_b(t) / 2`。
- 原生流程：精修拍频 `f_b(t)` + 配置波长 `λ₀` → `v_app(t)`。
- 边界清单：
  - `λ₀ = 1.55 µm` 是配置中的演示值，实验记录尚未确认；
  - 不含 LiF、折射率、入射角或窗口修正；
  - 单边 STFT 不提供速度符号。
- 版式：公式居中，右侧三条短说明，底部暗红警示条。

### 08 当前参数｜所有主要参数来自正式配置与 profile

- 核心句：参数入口已集中到配置与两个 profile，便于追溯每次运行。
- 表格：
  - `balanced`：Hann / 768 / overlap 640 / hop 128 / nfft 4096；
  - `high_time_resolution`：Hann / 512 / overlap 384 / hop 128 / nfft 4096；
  - 搜索带均为 0.05–2.0 GHz。
- 右侧原生代码块：`configs/demo_dual_profile.toml` 的关键字段与 `AnalysisProfile` 来源。
- 路径：`configs/demo_dual_profile.toml`、`src/dps_studio/core/analysis_profiles.py`、`src/dps_studio/core/workflow/config.py`。

### 09 参数取舍｜窗口长度同时决定时间支持与频率稳定

- 核心句：nfft 加密 FFT 网格，但不能单独提高真实频率分辨能力。
- 原生比较：
  - Balanced：窗口约 19.2 ns，窗限尺度约 52.1 MHz；
  - High time：窗口约 12.8 ns，窗限尺度约 78.1 MHz；
  - 两者 hop 都约 3.2 ns，重叠帧不是独立测量。
- 版式：一条水平取舍轴，上方“更短时间支持”，下方“更稳定频率估计”；右侧放参数解释。
- 科学边界：这些数值对应本次约 40 GS/s 的原始数据，不扩展为一般结论。

### 10 真实 profile 对比｜同一原始数据下，两套 profile 强调不同取舍

- 核心句：Balanced 在本次数据的平台区更稳定；High time 缩短时间支持，但不代表更高准确度。
- 图像：
  - `assets/real/ridge_balanced_ch1.png`；
  - `assets/real/ridge_high_time_ch1.png`。
- 实数对照（channel 1）：
  - 首个候选表观速度：537.9 vs 532.0 m/s；
  - 最大相邻频率步长：21.8 vs 25.0 MHz；
  - 峰—背景谱对比度中位数：52.5 vs 48.1 dB（非 SNR）。
- 版式：双图等宽，上方标题，下方三行原生数值表。

### 11 完整时间—速度｜正式结果只连接有定义的候选区间

- 核心句：前事件零是显示假设；核心表观速度保持 NaN。
- 主图：`assets/real/full_velocity_balanced_ch1.png`。
- 内容：候选区间、显示用两端点桥、事件起点参考线；未测区不插值。
- 版式：主图占 75%，右侧用三段简短定义区分“正式候选 / 显示零 / 显示桥”。
- 科学边界：不使用质量未筛选的 full preview 作为正式结果。

### 12 局部速度细节｜起跳、平台和下降段应分别检查

- 核心句：一条完整曲线会掩盖起跳窗口支持、平台抖动和下降段连续性。
- 三图：
  - `assets/real/event_detail_balanced_ch1.png`；
  - `assets/real/plateau_detail_balanced_ch1.png`；
  - `assets/real/decline_detail_balanced_ch1.png`。
- 版式：三列等宽，每图下方只有“起跳 / 平台 / 下降”与一句解释。
- 科学边界：局部图仍是基于临时波长的无符号表观速度。

### 13 双通道｜两通道趋势接近，但仍是两次独立观测

- 核心句：当前结果只支持“本次数据中趋势同量级”，不能推出准确度或自动择优。
- 主图：`assets/real/two_channel_velocity.png`。
- 数值：首个候选 537.9 / 531.8 m/s；峰—背景谱对比度中位数 52.5 / 55.8 dB；峰—竞争峰中位数 13.3 / 19.9 dB。
- 版式：左 72% 主图，右侧一列数值和两条解释。
- 科学边界：dB 是描述性谱对比度，不是 SNR；两通道没有平均、融合或选择。

### 14 开发历史｜软件从手动导出走向可追溯运行

- 核心句：变化的重点是参数、源数据与结果之间可回查，而不是曲线外观变化。
- 图像：
  - `assets/real/legacy_velocity.png`；
  - `assets/real/current_presentation_velocity.png`。
- 时间线：旧软件本地导出 → 不可变数据模型与 STFT → 亚频点精修与诊断 → 正式 workflow/config/manifest。
- 版式：上半部左右双图，下半部原生时间线。
- 科学边界：旧软件数据来源和参数尚待实验组确认，不能作为物理真值或算法准确度基准。

### 15 已完成能力｜已完成部分集中在数值处理与可追溯输出

- 核心句：软件能稳定复现当前数值过程，但科研解释仍需外部实验信息。
- 原生状态表：
  - 已实现：双通道只读输入、SI 单位、STFT、离散脊线、亚频点精修、无符号表观速度、双 profile 正式 workflow、CSV/PNG/manifest、描述性质量与连续性量；
  - 部分完成：命令行日常入口由脚本承担；
  - 未完成：GUI、LiF/折射率/角度修正、有符号速度、经验证的物理分支与可信判据。
- 版式：四列能力组，状态用暗红实线/灰线和文字，不用彩色圆点。

### 16 当前问题｜当前问题集中在物理校正与可信判据

- 核心句：诊断量已经可见，但还没有经实验验证的“可用/不可用”规则。
- 主图：`assets/real/two_channel_quality.png`。
- 问题：
  1. 1.55 µm 波长未由实验记录确认；
  2. LiF、折射率、入射角与不确定度模型未接入；
  3. 谱对比度和连续性仅描述数据，不等于 SNR、可信度或分支正确；
  4. 旧软件导出的来源、参数和处理步骤未确认。
- 版式：左 66% 图，右侧四行问题。

### 17 下一步｜按证据依赖顺序推进

- 核心句：先确认实验元数据和判据，再实现物理修正，最后完善界面与部署。
- 五步：
  1. 固化实验元数据：波长、窗口材料、几何条件与时间基准；
  2. 建立多数据集人工复核记录与分支判据；
  3. 给出 LiF/折射率/角度修正公式、单位与不确定度；
  4. 在双通道和双 profile 上做重复性与失效案例验证；
  5. 判据稳定后接入 GUI、打包和用户测试。
- 版式：左到右的五段依赖线，前四段暗红，最后一段灰色。

### 18 总结｜已经能复现表观速度；科研解释仍需验证

- 三句结论：
  - 已有：真实双通道输入、正式 STFT/脊线/亚频点精修、表观速度与可追溯输出；
  - 边界：临时波长、无 LiF 修正、无符号、无自动通道选择与物理可信判据；
  - 下一步：先补实验元数据与判据，再推进修正模型和 GUI。
- 版式：左侧暗红竖带，右侧三行大字；页脚“请老师批评指正”。
