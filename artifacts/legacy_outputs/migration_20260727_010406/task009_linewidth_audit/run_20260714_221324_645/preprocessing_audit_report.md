## 🪟 STFT 参数与含义

| 参数 | 当前值 | 数值含义 |
|---|---:|---|
| 窗函数 | periodic Hann | `get_window('hann', 768, fftbins=True)` |
| 窗长 | 768 点 | 约 19.2 ns 的固定时间支持 |
| 重叠 | 640 点 | hop = 128 点，约 3.2 ns |
| FFT 点数 | 4096 | 对每个 768 点窗做零填充以加密频率采样 |
| detrend | `False` | 无额外去趋势 |
| boundary / padded | `None` / `False` | 不在时域边界补帧 |
| scaling | `spectrum` | SciPy 频谱标度 |
| 单边谱 | `True` | 实信号非负频率 |
| 帧数 | 620 | 两通道一致 |

STFT 相对时间是窗中心坐标；绝对时间由记录起始时间加上该相对时间得到。首帧中心约位于原始起点后 9.6 ns，符合 768 点窗的半窗位置。`nfft=4096` 只加密频率网格，不创造额外真实频率分辨率；640 点重叠只提高帧密度，不把 19.2 ns 的窗支持缩短为 3.2 ns。当前原始数据通过均匀采样检查；若不通过，核心 API 会抛出 `NonUniformSamplingError`，不会继续误用中位采样率。

TASK-006 对每个有效频率逐点执行真空波长 1550 nm 下的表观速度换算，物理关系为

$$
v_{\mathrm{app}}=\frac{\lambda_0 f}{2}.

内部使用 SI 单位，输出为 m/s。离散候选速度与细化候选速度分别保存；展示速度另行构造，事件前零线只存在于展示层，事件外保持 `NaN`。当前没有正式 LiF 修正公式，也没有把表观速度冒充为校正速度。

## 🎯 Hop 参数终审

当前参数为窗口 768、重叠 640、hop 128、FFT 4096。平台段有 131 个候选点覆盖约 0.42 µs，下降段有 88 个候选点覆盖约 0.282 µs；频谱质量、连续性和双通道一致性均未显示帧密度不足。因而没有触发 hop 64 的条件，也未运行 hop 64 试验。

若改为 hop 64，预计帧数由 620 增至约 1,239，帧间隔由约 3.2 ns 变为约 1.6 ns，计算和绘图工作量近似翻倍；但真实时间支持仍由 768 点 Hann 窗决定，仍约 19.2 ns。当前证据下，增加显示采样密度不足以证明能增加真实时间分辨率或改善物理可信度。

最终建议采用方案 A：`window=768, overlap=640, hop=128, nfft=4096`。
